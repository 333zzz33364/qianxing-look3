## 【未读】FONT-A01 — 配置来源与恢复

【未读】【代码已审】[font-config.js](../../studio/host/font-config.js) 将默认配置放在 Windows `%APPDATA%/千星look3/font.json`，macOS/Linux 使用各自应用配置目录；`QXQY_FONT_CONFIG_PATH` 可显式覆盖配置文件位置。配置限制为 `auto/custom/system` 与 `game/all`；写入采用临时文件后改名。`[local-font.js](../../studio/host/local-font.js)` 启动时先读存档设置，但 `QXQY_FONT_PATH` 存在时优先加载该环境字体；环境字体无效时记录恢复错误，不回退到另一个已保存字体。环境来源锁定字体文件选择，仍允许仅改应用范围。自定义字体先验证绝对路径、TTF/OTF 类型和 32 MiB 上限，再写配置；无法验证时不会覆盖之前文件。运行进程保留启动时字体与 scope，保存后明确要求重启。

【未读】【测试证据】[Studio 字体局部日志](../../look3-workspace/整合/20261020-增量/字体设置-stage4.1-Studio局部.log)记录 7/7 通过，覆盖配置路径/模式、环境变量优先于坏配置、坏配置恢复、运行中字体文件替换后 Worker 仍用启动字节、画布与文字测量、字体端点限制及分发包排除本地字体目录。Web 测试用独立临时配置验证无效字体不会覆写原配置，并验证保存 scope 后当前 active scope 不变且 `restartRequired=true`。

【未读】【待验证】当前日志未显示新操作系统进程重启后重新读回已保存字体并实际绘制的端到端断言。配置读取和启动选择由代码实现，Web 浏览器刷新后能读到保存值，但该测试仍在同一 Node 进程内；所以“跨宿主重启已实测恢复”尚无证据。

## 【未读】FONT-A03 — Loopback 与本机数据边界

【未读】【代码已审】[local-font.js](../../studio/host/local-font.js) 的本机端点校验 socket 来源地址、Host、Origin 和常见代理/跨站头；字体文件只接受 GET/HEAD，按内容 SHA-256 ID 定址，不暴露文件名，响应 `no-store`、`nosniff` 和 same-origin CORP。设置路由仅处理本机直接访问，并限制 JSON 请求大小。Web 在有效本机字体已加载时拒绝非 loopback 绑定；Web 的字体设置接口额外受 Web loopback 开关约束。DSH 注册相同的字体路由，服务内部仍执行本机连接校验。工程状态、快照和分发包不包含字体路径或字体字节；合成 HTTP 测试确认 API state 不出现临时字体文件名或哈希，分发过滤排除字体容器和 `.local-fonts`。

【未读】【测试证据】[Web 局部日志](../../look3-workspace/整合/20261020-增量/字体设置-stage4.1-Web局部.log)记录 HTTP 用例通过并跳过未启用浏览器的子用例；覆盖 Basic Auth、错误 Origin、转发头和跨站请求拒绝、loopback 设置/字体读取，以及配置与工程导出边界。Studio 用例补充远端 socket、恶意 Host、代理头和关闭 settings 的检查。

【未读】【条件边界】Web 的非 loopback 启动拒绝条件是“实际成功加载的本机字体”；无效 `QXQY_FONT_PATH` 不会产生字体字节或路径响应，但这一无效环境变量与外部绑定的组合没有专门测试。DSH 若允许远端浏览器访问且宿主加载了自定义字体，字体端点会拒绝远端请求，而 Pixi 的 `initialize` 会等待字体加载 Promise；远程 DSH 渲染是否应降级到系统字体尚未验证。当前证据只覆盖 Web loopback 与路由级拒绝，不能据此宣称远程 DSH 预览可用。
