## 【未读】3. 径向填充与遮罩数据流

【未读】3.1 `imageFillSpec()`、`imageFillCoverage()` 和 `imageFillPolygon()` 位于共享 `studio/play/image-geometry.js`。径向 90/180/360 使用枚举起点、物理长宽比和顺/逆时针 sweep；Authoring 阶段遮罩、播放 Pixi 裁切、PNG 渲染与扁平 paint fallback 均接入该共享描述。运行时属性白名单、`session.js` 快照与 `compile.js` 均透传径向方向、顺逆时针、fill amount、软边参数、反转字段；增量场景签名也包含这些值，Lua 改字段能够使播放场景更新。

【未读】3.2 可见测试覆盖面：`studio/test/image-fill.test.mjs` 经真实 Lua API 检查字段进入 scene/paint，并以 PNG 独立采样水平、垂直及 Radial90/180/360；径向测试覆盖多个起点、顺逆时针和 0/中间/1 进度中的代表值。作者预览测试检查径向方向和缓存键。`web/test/image-mask-browser.test.mjs` 通过实际浏览器 Pixi 与 PNG 对照，包含 Radial360 两方向、Radial90/180 两方向和反转+Radial360 组合；日志 `look3-workspace/整合/20261020-增量/填充遮罩GPU第二轮.log` 记录该浏览器用例 1/1 通过。这里记录的是日志中既有结果，并非本次重跑。

【未读】3.3 软边规则以共享代码实现：Percentage 由 `(100 - range) / 200` 分别换算到宽、高，并将两轴 coverage 相乘；Pixel 使用实际宽度并保留播放端原有的四边最小值。**兼容差异需明确：旧作者预览原先将 X/Y 两轴 coverage 相乘，当前统一逻辑改为 Pixel 取 min；旧 Play/PNG 本来就是 min。** 新作者测试断言 min，但其“legacy Pixel minimum”指 Play 旧语义，不是旧作者实现。本轮为保留旧 Runtime Pixel 软边语义而采用 min 作为跨端兼容适配决定；这不是用户对具体 Pixel 算法的单独批准。该适配会改变作者预览角落表现，应如实说明，且尚无千星原生编辑器/游戏的对应视觉实证，不能笼统说所有旧 Pixel 行为完全不变。

【未读】3.4 **仍存在本地渲染边界：透明纹理的 alpha 轮廓没有跨阶段统一。** `editor-ui/stage-image-mask.js` 会将源图 alpha 乘入 mask coverage；Play/Pixi 和 PNG 的 mask 只由控件矩形、软边与 fill 几何计算，不读取遮罩图像 alpha。故相同参数在透明/半透明遮罩纹理下可能得到不同的作者预览与播放结果。当前源码注释已将其作为预览纹理轮廓策略，局部像素夹具验证的是各自路径；本批证据只支持矩形几何与列出的采样，不支持“任意图像透明轮廓下作者、播放、PNG 完全一致”。
